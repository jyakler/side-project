# 제공 형태

## Decisions

- 서비스는 Capacitor로 감싼 네이티브 앱(Android, iOS)으로 제공합니다. 화면은 현재 Next.js 웹 UI를 정적 export로 담아 유지하고, 백그라운드 위치 추적과 시스템 알림은 네이티브 플러그인이 맡습니다. 반경 진입 판정은 웹과 같은 JS 코드가 합니다.
- 순수 웹과 PWA는 제공 형태로 쓰지 않습니다. 웹은 개발 중 화면과 알림 로직을 확인하는 수단입니다.

## Boundaries

- 백그라운드 위치 추적과 알림 발생은 네이티브 쪽 책임이고, 웹 UI는 설정과 알림 해제 화면을 맡습니다.
- 어떤 플러그인을 쓸지는 이 결정이 정하지 않습니다. 선택 기준은 앱이 백그라운드이거나 화면이 꺼져 있어도 위치 갱신을 계속 받을 수 있는지와, 라이선스가 Apache 2.0 또는 MIT인지입니다(2026-10-22 사용자 조건).

## Why

`PRODUCT.md`는 "가동 뒤 서비스를 켜 두지 않아도 알림이 와야 한다"를 어떤 형태든 지켜야 하는 조건으로 둡니다. 웹의 Geolocation은 페이지가 백그라운드로 가면 멈추고 service worker에서는 쓸 수 없으며, Geofencing API는 표준화되지 않았습니다. Wake Lock은 문서가 비활성화되면 해제됩니다. Web Push는 서버가 필요해 "서버와 통신하지 않는다"는 경계와 충돌합니다. 그래서 웹으로는 핵심 조건을 만족할 수 없습니다. Capacitor는 기존 UI 스택을 보존하면서 이 조건을 만족하는 가장 작은 변경입니다.

## Reconsider when

- 브라우저가 백그라운드 위치 또는 geofence를 표준으로 지원할 때(w3c/geolocation#214 진행 상황)
- 선택한 Capacitor 플러그인이 실기기에서 백그라운드 위치 갱신을 안정적으로 하지 못한다는 근거가 나올 때

## Still-rejected alternatives

- 웹 포그라운드 전용 — 핵심 조건을 충족하지 못해 제품 약속이 성립하지 않습니다.
- Expo/React Native 등 UI까지 새로 쓰는 방식 — 이 저장소의 UI 스택과 검증 도구를 버려야 하고, 얻는 이점이 현재 범위에서 없습니다.
