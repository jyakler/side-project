# 지도와 주소 검색 서비스

## Decisions

- 지도 표시와 핀 선택은 Leaflet과 OpenStreetMap 타일을 사용합니다.
- 주소와 장소 검색은 OpenStreetMap Nominatim 공개 API를 사용합니다. 검색 결과의 좌표만 받아 지도에 핀을 찍습니다.
- 어느 쪽도 API 키나 가입이 필요하지 않습니다. 이 서비스 자체의 서버도 두지 않으므로 검색은 앱 안에서 직접 호출합니다.

## Boundaries

- 사용자 위치와 목적지는 지도 서비스에 보내지 않습니다. 지도 타일 요청과 주소 검색어만 외부로 갑니다. 지도에서 찍은 핀의 좌표를 주소로 바꾸는 역방향 검색은 목적지를 보내게 되므로 하지 않습니다.
- Nominatim 공개 서버의 이용 정책(초당 약 1회, 자동 완성 금지)을 지킵니다. 검색은 사용자가 검색을 실행할 때만 보냅니다.
- OpenStreetMap 저작자 표시를 지도에 둡니다.

## Why

사용자가 "키 없이 동작하게 하고 싶다"고 정했습니다(2026-10-22). 처음에는 Kakao 지도 Web API를 골랐지만, JavaScript 키 발급과 허용 도메인 등록이 필요하고 Capacitor WebView 출처에서 인증되는지도 확인되지 않았습니다. Leaflet과 OpenStreetMap은 키 없이 같은 흐름(검색해서 좌표를 얻고 그 위치에 핀을 찍기)을 제공합니다.

## Reconsider when

- 사용자 규모가 커져 Nominatim 공개 서버나 OpenStreetMap 타일 서버의 이용 정책을 넘어설 때(유료 또는 자체 호스팅 제공자로 옮깁니다)
- 한국 주소와 역 이름의 검색 품질이 사용 장면에서 부족하다는 근거가 나올 때(Kakao 등 국내 제공자를 다시 비교합니다)

## Still-rejected alternatives

- Kakao 지도, Naver 지도 — 한국 장소 검색 품질은 낫지만 키 발급과 도메인 등록이 필요해 "키 없이 동작"과 맞지 않습니다.
- 자체 프록시 서버로 키를 숨기는 방식 — 서비스 자체 서버를 두지 않는다는 제품 경계와 충돌합니다.
